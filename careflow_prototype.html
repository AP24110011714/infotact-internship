Read this first. Two kinds of data are used and every panel is tagged: REAL = your repo file Sepsis_Dataset_cleaned.csv (250 patients, one row each). SIMULATED = an event log created by generate_events.py for those same patients (activities after registration and all timestamps are simulated, seed 42). Process-mining results therefore demonstrate the method, not real hospital findings.

What CareFlow does

Hospitals record each step a patient goes through. CareFlow turns those records into an event log (case, activity, time) and then measures the real pathway: which routes patients take, where they wait, which steps repeat, and whether the expected order is followed.

1
Collect & clean – real patient table, checked for nulls and duplicates.
2
Build event log – case_id, activity, timestamp (simulated here because the real file has no event sequence).
3
Analyse – variants, directly-follows graph, waiting time, rework, conformance.
4
Present – KPIs and a case explorer, as in the Streamlit dashboard.
All panels here use the REAL patient file only. Descriptive analytics, not process mining.

Load your own event log

Select a CSV with columns case_id, activity, timestamp (e.g. the clean_log.csv your scripts use). Process Mining and Case Explorer then recompute on it. Nothing is uploaded; it stays in your browser.

Run it in your repo

python generate_events.py data/processed/Sepsis_Dataset_cleaned.csv data/processed/clean_log.csv
python main.py   # or your analysis scripts
streamlit run dashboard/app.py

Keep the "simulated" label in your report. If you later obtain a real event log, only clean_log.csv changes.
